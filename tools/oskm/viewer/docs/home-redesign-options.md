## 2. 当前首页问题

1. **子表实体不可见**：innerapis / features / syscaps / install_module_tags 只在 leaves 标签里以数字出现，无法点击进入
2. **归属链不清晰**：用户不知道"对外接口"是"部件"的子表、"模块标记"是"安装模块"的子表
3. **依赖方向不直观**：三段之间的箭头只写了"构建安装"/"init 拉起"，没体现外键关系
4. **典型用例与概念模型分离**：用户看完三段图后还得往下翻才看到用例

## 3. 方案 A：分层卡片（推荐）

保留三段结构，但每段内分两层：**主实体**（可点击进入） + **附属子表**（缩进展示，标明归属关系）。

```
┌─────────────────────────┐  构建安装  ┌─────────────────────────┐  init 拉起  ┌─────────────────────────┐
│ 部件信息                  │  ──────→  │ 系统文件                  │  ──────→  │ 运行时进程              │
│                          │           │                          │           │                         │
│ ┌─ 代码仓    525 ────→  │           │ ┌─ 安装目标  6579 ────→  │           │ ┌─ 系统服务  164 ────→  │
│ │  └ 安装模块 5501        │           │ │  └ 模块标记  1060       │           │ ├─ SA 服务   165       │
│ ├─ 部件      382 ────→  │           │ ├─ ELF 模块  3517       │           │ └─ HDI 设备   57        │
│ │  ├ 对外接口 1743       │           │ │  └ 依赖边  33360       │           │                         │
│ │  ├ 特性     1351       │           │ └─ 镜像视图              │           │                         │
│ │  └ 系统能力  306       │           │                          │           │                         │
│ └─ 编译开关  2952 ────→  │           │                          │           │                         │
│    └ 104 个被覆盖        │           │                          │           │                         │
└─────────────────────────┘           └─────────────────────────┘           └─────────────────────────┘

典型用例（6 张卡片，点击进入对应视图）
```

**优点**：
- 子表用缩进树形展示归属关系，一目了然
- 主实体可点击进入，子表也可点击
- 保留了"从源码到运行"的概念链
- 空间紧凑

**缺点**：
- 信息量较大，小屏可能需要折叠

## 4. 方案 B：矩阵表格

放弃卡片，用一张完整的表格展示所有实体，行=大类，列=实体名/行数/作用/依赖。

```
| 大类       | 实体         | 行数  | 作用                 | 依赖来源           |
|-----------|-------------|-------|---------------------|-------------------|
| 部件信息   | 代码仓       | 525   | git 仓 + HEAD       | —                 |
|           | 部件         | 382   | 构建索引             | 代码仓             |
|           | 对外接口     | 1743  | 部件→部件接口         | 部件               |
|           | 特性         | 1351  | 可配置开关名         | 部件 → 编译开关    |
|           | 系统能力     | 306   | 系统能力声明         | 部件               |
|           | 编译开关     | 2952  | GN declare_args     | 部件               |
| 系统文件   | 安装目标     | 6579  | 镜像文件清单         | 安装模块           |
|           | ELF 模块    | 3517  | 二进制依赖图         | 安装目标           |
| 运行时进程 | 系统服务     | 164   | init 声明           | 安装目标           |
|           | SA 服务      | 165   | SystemAbility       | 服务 + 安装目标    |
|           | HDI 设备     | 57    | HDF 设备驱动         | 服务 + 安装目标    |
```

**优点**：
- 信息密度最高，一屏看完所有实体
- 依赖来源列直接回答"这个数据从哪来"

**缺点**：
- 没有概念链的视觉引导
- 不如卡片直观
- 与现有设计风格差距大

## 5. 方案 C：关系图 + 入口

顶部是 Mermaid 关系图（简化版，只画大类和外键），下方是可点击的实体入口。

```
  ┌──────────┐     ┌──────────┐     ┌──────────┐
  │ 部件信息  │────→│ 系统文件  │────→│ 运行时   │
  │          │     │          │     │ 进程     │
  │ 代码仓   │     │ 安装目标  │     │ 服务     │
  │ 部件     │     │ ELF 模块  │     │ SA       │
  │ 编译开关  │     │          │     │ HDI      │
  └──────────┘     └──────────┘     └──────────┘
       │                │                  │
       ▼                ▼                  ▼
  ┌─────────────────────────────────────────────┐
  │ 代码仓(525)  部件(382)  编译开关(2952)       │
  │ 安装目标(6579)  ELF模块(3517)  服务(164)     │
  │ SA(165)  HDI(57)  对外接口(1743) ...         │
  └─────────────────────────────────────────────┘
```

**优点**：
- 关系图最直观
- 入口区可按大类分组

**缺点**：
- Mermaid 图在移动端渲染不理想
- 两次交互（看图→找入口→点击）

## 6. 推荐：方案 A（分层卡片）

**理由**：
1. 保留现有三段结构和视觉风格，改动最小
2. 子表缩进树形展示解决了"归属关系不可见"
3. 每个实体都可点击，不需要额外的入口区
4. 典型用例区保留在下方

**实施要点**：
- 主实体（代码仓/部件/编译开关/安装目标/ELF模块/服务/SA/HDI）：粗体行，可点击
- 子表（对外接口/特性/系统能力/模块标记/依赖边/安装模块）：缩进行，小字，可点击
- 安装模块从"系统文件"段的主实体提升为"安装目标"的父行
- 每个实体后跟行数（数据加载后）和一句话作用说明（未加载时显示）
- 箭头标注外键关系：部件→安装模块（component_id）、安装目标→服务（dest 匹配）
- 典型用例区从 6 张改为与一级菜单对齐的 3 组
